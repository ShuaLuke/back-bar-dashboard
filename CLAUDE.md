# Project notes

Static, single-page dashboard. No framework, no bundler. D3 v7.8.5 is loaded from cdnjs.

- Edit `src/template.html`, then run `python3 scripts/build.py` to regenerate `index.html`. Never edit `index.html` by hand.
- Data changes: edit `data/drinks_raw.tsv` (columns: group, restaurant, section, drink, price, ingredients; price may be blank), then run `scripts/normalize.py` before building. Add a rule to `RULES` in normalize.py for any new ingredient wording; rule order matters (liqueur rules before fruit rules, so "peach liqueur" isn't "Peach"). The script fails loudly on unmapped ingredients. After changing rules, diff the José Andrés mappings before/after to catch regressions. `data/sources.md` records each menu URL and read date; keep it current.
- Multiple restaurant groups: `GROUPS`, `REST_GROUP`, `gShort()` and `HOME` (the first group, José Andrés) in the template. The sidebar filters by group or restaurant; ops views use the selected restaurants; the Compare groups view (`renderGroups`) always uses every group. Zero-proof is detected from the section name (`ZERO_SECTION` in normalize.py).
- Each drink in drinks.json has `ings` (deduped canonical ingredients with `cat`) and `parts` (every menu ingredient line as `[raw, canonical]`, used for display).
- Categories (`cat`) roll up to 9 families via `CAT2FAM` in the template. Family colors are the `--f-*` CSS tokens.
- Light theme only, by design. Brand: "Well & Call" (bar slang: a well drink is the house pour, a call drink names the brand; the repo keeps its original `back-bar-dashboard` name so the Pages URL stays put), aperitivo orange `--accent`, teal `--teal`, fonts Geist + Geist Mono.
- Main JS entry points: `render()` re-renders everything on filter change; `setView(name)` switches views (`overview`, `ingredients`, `matrix`, `map`, `prep`, `price`, `gaps`, `groups`, `h2h`, `costs`, `about`). `renderChord`, `renderOps`, `renderOverview`, `renderGroups`, `renderH2H` and `renderCosts` each own one view. `h2h` compares two entities (`r:<restaurant>` or `g:<group>` ids, stored in `h2h` / localStorage `ja-h2h`).
- `og.png` (link preview, 1200x630) is rendered by `scripts/make_og.py` from `src/og-card.html` plus a headless screenshot of the built page with the detail drawer opened on the top pairing (see the `hook` in make_og.py). Re-run it after visible Overview or data changes. og:image URLs point at https://shualuke.github.io/back-bar-dashboard/.
- Template content above `<!--BODY-->` is emitted into `<head>` by build.py.
- Tooltips: give any element `data-tip="<html>"` (use `tipAttr()`, `ttRows()`, `ttList()`). One delegated handler does hover on desktop, tap-to-show / tap-again-to-open on touch, and focus for keyboard.
- The `costs` view uses made-up, adjustable per-ingredient-type costs (`COST_DEFAULT`) and a seeded random sales simulation (`simulate()`, `sim.seed`). Keep both labeled as assumed/simulated, never as real restaurant costs or sales.
- Detail views share one renderer, `renderInspect(box, ds, S, target, nav, opts)`, for ingredient / pair / category targets. It's used by the pairing map panel, the matrix panel (`renderPair`) and the overview drawer (`openDrawer`). Each caller passes `nav(target)` to decide what clicks do. Click rule: ingredients, pairs and categories open detail (the drawer on the Overview); summaries (restaurant rows, signals, "→" links) go to their page.
- Sub-map drawing helpers: `subMap()` (two-column links), `fanMap()` (one node to many, grouped by category: ingredient partners, or what else is in a pair's drinks) and `subChord()` (within one category), wired by `wireSubMap()`.
- Overview must fit one desktop screen (no page scroll) at 1280×720 and up; check this after layout changes.
- Neighborhood Restaurant Group covers ChurchKey, The Sovereign and Iron Gate only: Bluejacket's cocktail menu isn't published online and Birch & Barley closed in 2024 (now Mallard).
- Good next steps: split the template into css/js modules, add Vite, and add a monthly menu re-scrape to track changes.
